# 가림 수준 셋: 노출과 진단력 (#100, 2026-09-18)

조건 A~E(`ai-masking-repeat-review.md`)가 "무엇을 어디까지 가릴 수 있나"를 찾는 과정이었다면, 여기서는 그 답을 제품 설정 셋으로 굳혀 놓고 **노출과 진단력의 교환**을 다시 잰다.

원자료는 `ai-masking-levels.jsonl`이다. 실험 코드는 `AiMaskingTradeoffExperimentIT#가림_수준별_노출과_진단력을_18개_사례로_잰다`.

## 앞 회차와 달라진 것

**프롬프트에 대상 테이블의 전체 행수가 붙는다.** A~E와 조건이 다르므로 그 표들과 직접 비교하면 안 된다.

이유는 A~E에서 반복해 나온 응답 때문이다. L6(낮은 선택도)는 모든 조건에서 "테이블 전체 행수가 없어 판정할 수 없다"였고, M4(전 기간 날짜)는 값을 가리는 방식을 아무리 바꿔도 되살아나지 않았다. 선택도는 비율이라 분모가 있어야 판단할 수 있는데, 계획은 분자(`Plan Rows`, `rows_examined_per_scan`)만 들고 있다. 가림을 더 정교하게 만들어 풀 문제가 아니라 분모를 주면 되는 문제였다.

행수는 값이 아니라 규모라 가리지 않는다(`analysis/TableScale`).

## 가림 수준

| 수준 | SQL | 실행계획 | 예 |
|---|---|---|---|
| `NONE` | 원문 | 원문 | 제품 기본값. 사내 모델처럼 값이 밖으로 나가지 않을 때 |
| `STRUCTURE` | 값 가림 | 값은 지우고 모양만 | `'%@gmail.com'` → `'%?'`, `99000` → `?(5자리)`, `'2000-01-01'` → `'?(약 27년 전)'` |
| `FULL` | 값 가림 | 전부 `?` | `'%@gmail.com'` → `'?'`, `99000` → `?` |

설정은 `dbtower.masking.ai-plan-level`이고 `mask-ai-plan`이 켜져 있을 때만 걸린다.

값이 진단을 가르는 사례 15개와 대조군 3개다(`src/test/resources/experiments/ai-masking-level-cases.json`).

| `%` 위치 | 앞 와일드카드는 인덱스를 못 쓰고, 뒤 와일드카드는 쓴다 | M2·M3·P1·P2 |
| 날짜의 거리 | 데이터 시작보다 이른 날짜면 전 행이 대상이다 | M4·M5·P5·P6 |
| 값의 분포 | 어느 상태 값인지가 선택도를 가른다 | M6·M7 |

| 개수 | IN 목록에 든 값의 수만큼 조회가 반복된다 | P7 |
| 깊이 | OFFSET 숫자만큼 앞 행을 읽고 버린다 | M8 |
| 대조군 | 값과 무관하게 구조만으로 판정된다 | C1·C2·C3 |

| NONE | STRUCTURE | FULL |

## 뺀 사례 넷

기대한 원인과 실제 실행계획이 어긋나 가림과 무관하게 틀리는 사례다. 집계에서 뺐다.

| 사례 | 왜 뺐나 |
|---|---|
| M4 | 기대는 "전 기간이라 풀스캔이 정상"인데 계획은 `(amount, created_at)` 인덱스의 인덱스 풀스캔이다. 모든 조건이 "복합 인덱스 선두 누락"으로 결론 냈고 계획에 비춰 그 판단이 옳다 |
| P2 | 기대는 "뒤 와일드카드라 인덱스 범위 조회가 가능(정상)"인데 PostgreSQL은 Seq Scan을 골랐다. 기본 콜레이션의 btree 인덱스는 `LIKE` 접두사 조회에 쓰이지 않는다 |
| P7 | 기대는 "IN 목록이 열 개라 조회를 열 번 반복"인데 계획은 `= ANY` 한 번의 Index Scan이다. 반복 조회가 일어나지 않았다 |
| C3 | 대조군인데 규칙이 짚은 Seq Scan이 조건 없는 조인 상대 쪽이라, 모든 조건이 "지적이 번지수를 틀렸다"로 끝난다 |

## 무엇이 차이를 만들었나

**`%` 위치가 가장 크게 갈렸다.** P1(PostgreSQL 앞 와일드카드)은 STRUCTURE에서 세 번 다 원인을 짚었고 FULL에서는 세 번 다 "실제 패턴을 확인할 수 없다"로 내려갔다. M2(MySQL 같은 사례)도 같은 방향이다. 계획에 `'%?'`가 남으면 앞 와일드카드라는 사실 자체가 남고, `'?'`가 되면 사라진다.

**날짜의 거리도 쓰였다.** P5의 응답은 `'?(약 27년 전)'`을 직접 인용하며 "조건값이 약 27년 전 날짜라 거의 모든 행이 걸린다"고 적었다.

**숫자 자릿수는 이 사례들에서 결정적이지 않았다.** P3·P4는 세 조건 모두 맞혔는데, 자릿수가 아니라 계획의 추정 행수(199,978 대 2,037)로 갈렸기 때문이다.

**M8(깊은 OFFSET)은 가리면 잃는다.** NONE은 `OFFSET 190000`을 보고 짚었지만 가린 조건들은 커버링 인덱스라는 관찰에서 멈췄다. 자릿수(`?(6자리)`)만으로는 되살아나지 않았다.

**대조군 C1·C2는 세 조건 모두 아홉 번 맞혔다.** 값과 무관하게 구조로 판정된다는 전제가 섰다는 뜻이다.

## 판정자를 셋으로 늘렸다 (#131)

기본값을 가림 켜짐으로 바꿀지 정하려고 이 표를 다시 봤는데, 두 판정의 일치가 126칸 중 77칸(61%)뿐이었다. 그 상태로는 "STRUCTURE가 정확도를 잃지 않는다"를 근거로 쓸 수 없다. 그래서 착수 전에 규칙을 먼저 적었다.

> 판정 일치율을 먼저 올린다. 일치가 80%를 넘지 않으면 기본값을 바꾸지 않는다.

같은 기준표로 로컬 모델(Ollama `llama3.1:8b`)을 하나 더 돌렸다. 스크립트는 `judge3_masking.py`, 원자료는 `ai-masking-judge3.jsonl`(162건, 파싱 실패 0)이다. 아래 수치는 `judge_agreement.py`가 이 문서의 표와 그 파일을 읽어 다시 뽑는다 — 사람이 옮겨 적지 않는다.

| 짝 | 일치 |
|---|---|
| 이 세션 - qwen3:14b | 77/126 (61%) |
| 이 세션 - llama3.1:8b | 80/126 (63%) |
| qwen3:14b - llama3.1:8b | 96/126 (76%) |
| **셋 다 같음** | **64/126 (51%)** |

**80%를 넘지 못했다. 그래서 기본값을 바꾸지 않는다.**

### 그래도 표 전체가 무의미한 것은 아니다

불일치가 어디서 나는지를 같이 봐야 한다. 갈린 칸을 짝별로 분해하면 거의 전부 확정과 후보 사이다.

| 짝 | 확정 ↔ 후보 | 후보 ↔ 놓침 | 확정 ↔ 놓침 |
|---|---|---|---|
| 이 세션 - qwen3:14b | 43 | 5 | 1 |
| 이 세션 - llama3.1:8b | 41 | 5 | 0 |
| qwen3:14b - llama3.1:8b | 29 | 1 | 0 |

세 판정이 확정과 놓침으로 **정반대로** 갈린 칸은 126칸 중 하나다(M5/NONE/2). 판정자들이 갈리는 지점은 "원인을 봤나"가 아니라 "확정이라 부를 만큼 봤나"다. 확정선이 판정자마다 다른 것이지, 응답의 내용을 반대로 읽는 것이 아니다.

그래서 절대값은 못 쓰지만 **순서는 셋 다 같다.**

| 판정자 | NONE | STRUCTURE | FULL |
|---|---|---|---|
| 이 세션 | 38/42 (90%) | 35/42 (83%) | 30/42 (71%) |
| qwen3:14b | 30/42 (71%) | 23/42 (55%) | 16/42 (38%) |
| llama3.1:8b | 27/42 (64%) | 24/42 (57%) | 19/42 (45%) |
| 다수결 | 33/42 (79%) | 28/42 (67%) | 22/42 (52%) |

`llama3.1:8b`는 STRUCTURE를 NONE보다 낮게 보지만 FULL보다는 높게 본다. 세 판정과 다수결 모두에서 STRUCTURE는 FULL보다 NONE 쪽에 가깝다.

## 고른 것

**기본값은 바꾸지 않는다.** `mask-ai-prompt`·`mask-ai-plan`은 꺼진 채로 두고, 켰을 때 걸리는 수준만 `STRUCTURE`로 한다.

두 가지를 나눠서 정했다.

**켰을 때의 수준이 STRUCTURE인 근거는 섰다.** 노출은 STRUCTURE와 FULL이 똑같이 0이다(실험 코드가 직접 센 값이라 판정자와 무관하다). 그러면 남는 기준은 진단력뿐이고, 세 판정자 전부 STRUCTURE를 FULL보다 위로 봤다. 더 가려서 얻는 것이 없는데 진단을 잃을 이유가 없다.

**기본값을 켜는 근거는 서지 않았다.** 그러려면 "STRUCTURE가 NONE 대비 정확도를 잃지 않는다"가 필요한데, 세 판정 모두 NONE > STRUCTURE로 본다. 손실 폭은 판정자마다 7%p·16%p·7%p로 제각각이고, 그 폭을 믿으려면 일치율이 받쳐 줘야 하는데 51%다. **가림을 켜면 무엇을 잃는지 아직 수치로 말할 수 없다.** 모르는 채로 모든 사용자의 기본 동작을 바꾸지 않는다.

가려야 하는 환경은 설정 두 줄로 켠다.

```yaml
dbtower:
  ai:
    mask-ai-prompt: true
    mask-ai-plan: true
    ai-plan-level: STRUCTURE
```

이 판정을 뒤집으려면 필요한 것은 판정자를 더 늘리는 것이 아니라 **확정선을 기준표에 못 박는 것**이다. 지금 기준표의 "확정"은 "분명히 지목했다"인데, 그 '분명히'를 모델마다 다르게 읽는다.

## 판정 방법

응답 원문을 읽어 기대 원인 쪽으로 결론을 냈는지 본다. 기준은 A~E와 같다.

- ✓ 기대 원인 쪽으로 결론을 냈다
- △ 후보로만 들거나 원인 판정에 "확인할 수 없다"를 붙였다
- ✗ 기대 원인을 들지 않았거나 다른 원인으로 결론 냈다

판정자는 셋이다. 이 AI 코딩 세션이 한 번, 로컬 오픈소스 모델 둘(Ollama `qwen3:14b`·`llama3.1:8b`)이 각각 한 번 매긴다. 기준표는 호출 전에 고정했고 셋에게 같은 것을 준다.

**판정자 셋 다 사람이 아니다. 이 사실을 결과보다 먼저 적는다.** 다수결은 "정답"이 아니라 "세 판정이 같은 자리가 상대적으로 믿을 만하다"는 뜻일 뿐이다. 그래서 다수결로 결론을 뒤집지 않고, 일치율이 낮으면 결론을 내지 않는 쪽을 골랐다(#131).

재현:

```bash
python3 docs/experiments/judge3_masking.py \
    docs/experiments/ai-masking-levels.jsonl \
    src/test/resources/experiments/ai-masking-level-cases.json \
    docs/experiments/ai-masking-judge3.jsonl llama3.1:8b
python3 docs/experiments/judge_agreement.py
```

## 기준표를 고쳐 봤고, 더 나빠졌다 (#137)

#131에서 판정 일치가 51%에 그쳤고 갈린 칸이 거의 전부 확정과 후보 사이였다. 그래서 병목을 기준표의
"분명히 지목했다"로 보고 **확정선을 검사 가능한 조건으로 다시 썼다.** 결과는 가설과 반대였다.

### 설계

판정자를 늘리지 않고 **기준표만** 바꾼다. 로컬 모델 셋에게 같은 응답 162건을 옛 기준표(v1)와
새 기준표(v2)로 각각 판정시킨 3 x 2다. 실행 조건도 고정했다 — `think: false`, `temperature: 0`,
모델은 `keep_alive`로 띄워 둔다. 판정자와 실행 조건이 고정이므로 일치율 차이는 기준표 차이다.

원자료는 `ai-masking-judge-rubric-ab.jsonl`(972건, 파싱 실패 0), 스크립트는 `judge_rubric_ab.py`와
`judge_rubric_agreement.py`다. 아래 수치는 후자가 원자료를 읽어 다시 뽑는다.

### 새 기준표는 무엇을 바꿨나

옛 기준표의 확정은 "기대 원인을 분명히 지목했다"였다. 새 기준표는 그 '분명히'를 둘로 나눴다.

1. 기대 원인 **하나로** 결론 냈는가
2. 그 결론 문장에 **불확실 표현이 없는가**

둘을 모두 만족할 때만 확정이다. 사용자가 실제로 판정한 사례를 예시로 박았다 —
"가장 유력한 원인은 X입니다. 다만 확인할 수 없습니다"는 원인을 하나로 좁혔어도 **후보**다.

### 결과: 일치율이 떨어졌다

| | 옛 기준표(v1) | 새 기준표(v2) |
|---|---|---|
| qwen3:14b - llama3.1:8b | 75% | 67% |
| qwen3:14b - qwen3:8b | 88% | 62% |
| llama3.1:8b - qwen3:8b | 77% | 39% |
| **셋 다 같음** | **88/126 (70%)** | **43/126 (34%)** |

**70%에서 34%로 절반이 됐다. 새 기준표를 쓰지 않는다.**

### 왜 나빠졌나 — 규칙이 검사 가능해 보였을 뿐이다

새 기준표에 불확실 표현의 예를 나열했다. 그 단어들이 응답에 얼마나 흔한지 세어 봤다.

| 표현 | 162건 중 |
|---|---|
| `추정` | 161 (99%) |
| `다만` | 117 (72%) |
| `수 있` | 99 (61%) |
| `알 수 없` | 72 (44%) |
| **하나라도 든 응답** | **162 (100%)** |

**전부다.** 실행계획 텍스트에 "추정 행수"가 들어 있어 응답이 그것을 인용만 해도 걸린다. 규칙을 문자
그대로 적용하면 162건이 모두 후보가 된다.

실제로 그렇게 갈렸다. 새 기준표에서 판정자별 확정 비율은 이렇다.

| 판정자 | NONE | STRUCTURE | FULL |
|---|---|---|---|
| llama3.1:8b | 0/42 (0%) | 1/42 (2%) | 1/42 (2%) |
| qwen3:14b | 18/42 (43%) | 16/42 (38%) | 9/42 (21%) |
| qwen3:8b | 24/42 (57%) | 20/42 (48%) | 17/42 (40%) |

`llama3.1:8b`는 목록을 문자 그대로 받아 확정을 사실상 내지 않았고, `qwen3:8b`는 느슨하게 적용했다.

규칙의 진짜 판단은 "불확실 표현이 있는가"가 아니라 **"그것이 원인 문장에 붙었는가"**였고, 그건 원래의
'분명히'만큼 주관적이다. 검사 가능한 조건으로 바꾼 것이 아니라 **갈릴 축을 하나 더 만든 것이다.**
규칙에 예시 단어를 넣을 때는 그 단어가 코퍼스에 얼마나 흔한지 먼저 세어야 했다.

### 같은 실험에서 나온 진짜 지렛대

옛 기준표의 셋 다 같음이 **70%다.** #131에서 같은 기준표로 잰 것은 51%였다. 기준표는 같은데 19%p 차이가 난다.

무엇이 달랐나 — 판정자 묶음과 실행 조건이다.

| | #131 | 이번 |
|---|---|---|
| 판정자 | 이 세션(Claude) + qwen3:14b + llama3.1:8b | 로컬 모델 셋 |
| 사고 과정 | 모델마다 다름 | 전부 끔 |
| temperature | 지정 안 함 | 0 |
| 셋 다 같음 | 51% | **70%** |

#131의 낮은 일치는 기준표보다 **섞인 판정자 묶음**에서 왔다. 이 세션의 확정 비율은 90/83/71%로 로컬
모델들(64~83%)보다 눈에 띄게 후했고, 그 차이가 일치율을 끌어내렸다. 실행 조건을 고정한 것도 같이 작용했다 —
`temperature`를 안 정하면 같은 입력에 다른 라벨이 나올 수 있어 판정이 재현되지 않는다.

### 순서는 더 단단해졌다

옛 기준표·고정 조건에서 세 판정자 **전부** 같은 순서다.

| 판정자 | NONE | STRUCTURE | FULL | 순서 |
|---|---|---|---|---|
| qwen3:14b | 83% | 67% | 52% | NONE > STRUCTURE > FULL |
| llama3.1:8b | 64% | 48% | 43% | NONE > STRUCTURE > FULL |
| qwen3:8b | 83% | 69% | 64% | NONE > STRUCTURE > FULL |

#131이 "절대값은 못 쓰고 순서는 쓴다"로 내린 결론이 더 잘 통제된 측정에서도 그대로 선다.

### 기본값은 여전히 바꾸지 않는다

70%도 #131이 착수 전에 정한 80%에 못 미친다. 새 기준표는 34%라 더 멀다. **기본값 전환의 근거는 서지 않는다.**

### 다음 병목

기준표의 문장이 아니라 **판정자 묶음의 동질성과 실행 조건**이다. 이번에 그 둘을 고정해 51% -> 70%를 얻었다.
남은 30%를 줄이려면 다음 중 하나가 필요하고, 셋 다 이번 범위 밖이다.

- 사람이 매긴 정답 묶음. 지금은 판정자가 전부 모델이라 다수결이 "정답"을 뜻하지 않는다
- 판정을 라벨 하나가 아니라 근거 인용과 함께 받게 해 갈린 칸의 이유를 대조하는 것
- 같은 계열 모델을 쓰는 것. qwen3:14b와 qwen3:8b의 일치가 88%로 가장 높았다 — 다만 이건 일치가
  높아지는 것이지 정확해지는 것이 아니다. 같은 편향을 공유하면 같이 틀린다
